Section 1

Introduction, scope & conventions

1.1 Purpose

This Functional Specification defines, in implementable detail, the behaviour, structure, and visual design of the BlueWhale Stack corporate website. It is the contract between design and engineering: every page, navigation element, component, state, and interaction is specified so the build is unambiguous and testable.

1.2 Scope

In scope: the public marketing website — all pages, the global navigation (header, mega-menus, footer), the design system, responsive behaviour, forms, and non-functional standards. The Partner Portal application itself is a separate product; the website links into it and markets it, but does not re-implement it.

1.3 Conventions

  • FR-XXX — a numbered functional requirement (testable).
  • Must / Should / May — priority per RFC 2119 (Must = required for launch).
  • Spacing values use an 8 px base scale; breakpoints are mobile-first.

1.4 Technology baseline

Next.js 15 (App Router) + TypeScript + Tailwind CSS v4, with a typed content layer and a CMS-ready seam (per the SOW). Server-rendered for SEO and speed.

Brand-aligned. All color, logo, and typographic direction in this FSD derive from the supplied BlueWhale Stack Identity Guidelines v0.1101. The horizontal logo, the whale-in-stacked-blocks logomark, and primary blue #002da1 are the canonical identity; this document specifies how they are applied on the web.

4.4 Mega-menu behaviour

  • FR-NAV-011 Opens on hover after a 120 ms intent delay; closes on mouse-leave after 200 ms or on Esc.
  • FR-NAV-012 Fully keyboard operable: items are buttons with aria-haspopup/aria-expanded; arrow keys move within the panel; focus trap while open; Esc returns focus to the trigger.
  • FR-NAV-013 Only one mega-menu open at a time; opening another closes the previous.
  • FR-NAV-014 Panel animates with an 8 px fade-slide (150 ms); respects prefers-reduced-motion.

4.5 Utility navigation

A secondary tier (right of header, and a thin top bar on wide screens) carries items outside the five buckets: Resources, Docs, Search, Login (to product / Partner Portal), and optional Region/Language. This keeps the five primary buckets clean while these high-intent links stay reachable.

4.6 Mobile navigation (< 1024 px)

  • FR-NAV-020 A hamburger opens a full-height drawer; the five buckets render as accordions revealing the same links as the desktop mega-menus.
  • FR-NAV-021 Utility links (Resources, Docs, Login, Search) sit below the accordions; "Book a demo" is pinned to the drawer footer.
  • FR-NAV-022 Body scroll locks while the drawer is open; the drawer is keyboard- and screen-reader-accessible.

Section 6

UI/UX design system — brand foundations

The visual language extends the BlueWhale Stack Identity Guidelines v0.1101 to the web: the same primary blue, the architectural logic of the stacked-blocks logomark, and bold, geometric typography — executed as a refined, modern-enterprise system.

6.2 Typography

The wordmark uses a bold, squared, geometric sans-serif (per the identity). The web type system mirrors that character for display while keeping body text highly legible.

FR-TYP-001 Type scale (fluid, clamp()): H1 36–60px · H2 28–40 · H3 20–26 · body 16–18 · small 13–14. Line-height 1.1–1.25 headings, 1.55 body. Max line length ~70ch.

Open brand item. Confirm the licensed display/brand font from the full guidelines; the recommendations above are close geometric matches and a one-line swap.

6.3 Grid, spacing & radius

Grid

12-column, 1280px max content width, 24px gutters; 20px outer padding (mobile), generous section rhythm (80–96px desktop).

Spacing

8px base scale (4/8/12/16/24/32/48/64/96). Consistent vertical rhythm between sections.

Radius & elevation

Cards 16px, buttons 8px, pills 999px. Two shadows: soft (cards), brand-glow (primary/hover). Echoes the rounded stacked-blocks.

6.4 Logomark as a design motif

The stacked-blocks-with-whale logomark is more than a logo: its 2×2 block grid becomes a recurring visual device — section dividers, the "platform layers" diagram language, bento-style card grids, and loading states — tying the site visually to the identity.
